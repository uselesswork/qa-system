# 第九阶段 工程基线与代码重构

> 对应后续工程整理（不对应原实验模块） · [返回项目说明](../README.md) · [上一阶段](第八阶段-答案感知重排.md)

## 一眼看懂本阶段

本阶段没有引入新模型或存储组件，而是把前八阶段已经能工作的原型整理为可回归、可解释的代码基线。重点解决“同一请求重复生成答案”“标题切分器接上了却没有生效”“接口返回形状在不同路由重复实现”“无密钥测试误触发追踪”等问题。当前 `pytest -q` 只收集新的离线测试；旧 `src/test/` 继续作为实验脚本保存。

| 项目 | 本阶段结果 |
| --- | --- |
| 目标 | 保留原有单轮、多轮和证据展示能力，减少重复调用并建立无密钥回归 |
| 问答链路 | 聚合回答不再附带一次被丢弃的普通回答；流式文本和最终证据来自同一次执行 |
| 检索与切分 | 复用问题向量；Markdown 标题可识别、保留导言和位置元数据 |
| 启动与接口 | 异步组装完成索引后才提供服务；统一三种问答路由的证据序列化 |
| 测试 | `pytest -q` 默认只运行 `tests/`；假组件验证主要分支与 HTTP 契约 |

这不是“RAG 准确率提升”的声明。改动主要是移除明确的重复计算、修复已复现的切分缺陷，并让行为有离线回归保护；真实模型效果仍需单独评测。

## 具体完成的工作

### 统一普通回答与流式回答的主链路

`RAGCore._retrieve()` 集中执行召回、可选 Embedding 重排及可选答案感知细排。`answer()` 和 `stream_answer_with_result()` 共用它，因此同一个配置不会因入口不同而漏掉细排。配置了答案聚合器时，直接使用聚合器返回的 `AggregatedAnswer`，不再额外构造普通回答 Prompt 并生成一条随后被丢弃的答案。

`/ask/stream` 读取 `stream_answer_with_result()` 的增量文本和最终 `RAGResult`，不再流出文本后再次调用 `answer()`。保留原有 `stream_answer()` 纯文本接口以兼容只消费文字的调用方。需要特别区分：未配置聚合器时可以使用模型的真实增量生成；当前 Web 配置了跨文档聚合器，它要先完成多次模型分析和综合，再把完整答案分块输出。后者不是逐 token 实时生成。

### 修复标题切分和片段元数据

原标题正则把 `\s` 误写成字面量双反斜杠；同时 `TextCleaner` 在切分前把 Markdown 换行压成一个空格，导致普通 `# 标题` 走回退长度切分。现在 Markdown 路径调用 `clean(..., preserve_newlines=True)`，标题正则按行匹配一级至六级标题。标题前的导言也会保留为片段。每个标题片段写入 `chunk_id`、`char_start`、`char_end`、`heading`、`semantic`；偏移对应清洗后的文档文本。没有标题的 Markdown 继续回退到 `TextSplitter`。

本次修复改变了示例 Markdown 启动索引的片段边界，因此首次启动会重新计算这些片段的 Embedding。标题按整节切分，尚未对极长章节进一步分段；它可能增加 Prompt 长度，不能把“按标题切分成功”直接等同于回答更准确。

### 去除重复的问题向量与相似度实现

`SimpleRetriever.retrieve_with_vector()` 返回 `RetrievalBatch(results, query_vector)`。`RAGCore` 的 Embedding 重排直接复用检索时已经计算的问题向量；旧的 `retrieve()` 仍返回 `SearchResult` 列表。只实现旧接口的其他检索器通过基础类默认实现兼容，但没有向量可复用时会补算一次。内存库、Embedding 重排和证据聚合统一调用 `src/utils/similarity.py` 的余弦相似度函数；零向量时返回 0，避免除零产生 `nan`。

### 明确组件契约和启动职责

两个原本同名的答案感知聚合器现在分别叫 `AnswerAwareAggregator`（先生成答案后选证据）和 `CrossDocumentAnswerAggregator`（逐片段分析后综合回答）；当前 Web 使用后者。二者都实现 `BaseAnswerAggregator` 并返回 `AggregatedAnswer`。只选证据的 `AnswerAggregator` 继续实现 `BaseEvidenceAggregator`，不能不加适配就替换答案聚合器。没有候选时，两种答案聚合器返回空证据和明确的无法回答文本，不调用模型。异步的 `AnswerAwareReranker` 不再继承同步重排接口，其未使用的问题向量参数也已删除。

`app/rag_app.py` 的 `load_chunks()` 负责按文件名顺序读取和切分固定资料；异步 `build_rag_core()` 负责创建组件、计算 Embedding 并写入内存库。`app/main.py` 的 lifespan 等待建索引完成，不再通过向量库的 `_pending_chunks`、`_embedder` 私有字段传递启动状态。缺少 `OPENAI_API_KEY` 或示例文档没有可索引内容时，启动阶段抛出明确错误；环境变量和根目录 `.env` 仍按原约定使用。

### 收敛接口与会话代码

`/ask`、`/chat`、`/ask/stream` 共用证据和元数据序列化：来源路径统一转成字符串、分数统一保留四位小数、元数据中的路径可递归转为 JSON 值。`ChatService` 仅在 RAG 和证据转换都成功后，调用 `ChatMemory.append_turn()` 记录完整用户/助手消息对。未使用的 `ChatSession` 文件已移除，误写的 `src/chat/_init_.py` 已替换为标准 `__init__.py`；当前进程内会话机制不依赖被移除的类。

## 请求与数据流

```text
启动：.env / 环境变量 → 配置检查 → Markdown 读取与标题切分
     → 批量 Embedding → 内存向量库 → RAGCore / ChatService 就绪

问答：query → 检索（同时取得 query_vector）→ 可选重排
     → 有聚合器：综合答案 + 证据；无聚合器：Prompt + 模型回答
     → RAGResult → /ask、/chat 或同一次 /ask/stream 的最终事件

测试：pytest -q → 仅 tests/ → 假检索器 / 假模型 / ASGI 客户端
```

`src/test/` 原实验脚本保留为手动对比入口，其中有真实模型调用和不符合 pytest 夹具约定的函数。`pytest.ini` 把默认收集范围限定在 `tests/`，避免把那些脚本误当成无密钥 CI 测试。需要单独运行旧 Loader/Prompt 安全样例时，可以在命令中显式列出文件；真实模型实验也必须显式选择。

## 验证与限制

在本机虚拟环境执行 `python -m pytest -q`，本阶段新的默认回归共 18 个测试通过；另有 4 个可显式运行的旧 Loader/Prompt 用例。回归使用假 Embedding、假模型与 ASGI 客户端，覆盖标题识别及无标题回退、位置元数据、问题向量复用、旧检索器兼容、零向量相似度、异步启动入库、缺少 Key 的错误、聚合器契约、普通/流式一致性、`/ask`、`/chat`、`/ask/stream` 响应和失败时不留下半轮对话。pytest 入口显式关闭 LangSmith 追踪，使离线测试不上传内容。依赖安装命令只在根 README 维护，不新增 requirements 文本文件。

尚未运行真实 Embedding/Chat 模型、LangSmith 联调、浏览器端到端、多进程或容器验证。向量和会话仍在进程内，Web 仍只装载 `data/model12/*.md`；没有上传、账号权限、持久化或完整的成本统计。标题切分和接口重构的测试证明行为一致，不证明回答质量提升。下一阶段如引入数据库或向量服务，应在这套离线基线上另加隔离集成测试。
