## 一眼看懂本阶段

本次先为“可上传、可持久化的知识库”确定数据库结构与迁移入口，没有把现有网页切换到数据库。MySQL 保存知识库、文档、片段的业务元数据和片段正文；后续 Qdrant 将保存向量，并以片段 UUID 作为点 ID。本机 `qa_system` 数据库已由用户创建，本轮已连接该库执行初始迁移，并加入一套可重复运行的演示数据。初始迁移还在隔离的 SQLite 临时库验证过，并生成过 MySQL 离线 SQL。

## 具体完成的工作

### 三张表的职责

`knowledge_bases` 记录知识库 UUID、名称、描述及创建/更新时间。现阶段没有账号体系，因此不声称已经按用户隔离；阶段 11 加账号时需专门迁移所有权结构。

`documents` 属于一个知识库，记录原文件名、格式、存储键、SHA-256、字节数、索引状态、错误信息和时间。状态限于 `pending`、`indexing`、`ready`、`failed`。同一知识库内 `(knowledge_base_id, sha256)` 唯一，后续上传服务可以据此定义重复内容的处理；相同文件在不同知识库允许分别入库。`storage_key` 目前可空，因为文件保存机制尚未实现。

`chunks` 属于一个文档，记录片段 UUID、文档内序号、正文、标题、PDF 页码、字符区间和创建时间。同一文档的 `ordinal` 唯一。后续写 Qdrant 时应复用 `chunks.id` 作为向量点 ID，使删除、重建和引用能对齐两个存储。外键采用删除级联；删除知识库会删除其文档及片段的数据库记录，但**不会自动删除未来 Qdrant 中的向量**，这需要服务层协调和失败补偿。

### 连接与迁移

`src/db/session.py` 在实际调用时才从 `.env`/进程环境读取 `DATABASE_URL`，导入模块不会连接数据库；缺失配置会明确报错。生产连接示例使用 `mysql+pymysql` 和 `utf8mb4`。`alembic.ini` 不保存连接串，`migrations/env.py` 直接读取同一配置。初始迁移创建三张表、唯一约束、状态与非负值检查及常用索引。后续结构变更应新增迁移，不修改已应用的初始迁移。

MySQL 数据库本身需由有权限的本地管理员先创建；`scripts/create_database.sql` 只提供可复用的 `qa_system` 建库语句，不包含密码或用户凭据。用户创建数据库并在被 Git 忽略的 `.env` 配置本机连接后，本轮执行了 `alembic upgrade head`，确认版本为 `0001_initial`，三张业务表和 `alembic_version` 均存在。没有把连接密码写进代码或文档。

### 可重复的演示数据

`scripts/seed_demo_data.py` 读取仓库现有的 `data/model12/doc1.md`～`doc6.md`，通过与 Web 相同的 Markdown 清洗和标题切分流程生成片段。六份资料分到 5 个知识库：原有的 RAG 演示资料保留 `doc1`、`doc2`，其余四个库分别对应候选片段差异、关键词噪声、重排目标和失败机制案例。每个库的 `description` 概述所含资料及未建向量索引的状态；再次播种只补全空描述，不覆盖非空的自定义描述。知识库、文档及片段使用确定性 UUID；原有知识库、`doc1`、`doc2` 的 ID 和归属不变。文档记录实际文件 SHA-256、大小和相对路径。播种在单个数据库事务中完成：输入缺失或已播种内容与当前文件冲突时停止，不覆盖已有记录。空库首次运行新增 5 个知识库、6 份文档、6 个片段；在原先 `1/2/2` 数据基础上升级时新增 `4/4/4`；再次运行不新增业务记录。

这六份文档保留 `pending` 状态，因为尚未写入 Qdrant。数据库中的片段正文仅供后续服务开发和关系查询验证，**不能据此称当前网页已支持持久化知识库检索**。

## 本机建库与验证

依赖安装命令只在根 README 维护，不新增 requirements 文件。全新环境仍须先用 MySQL 管理员执行 `scripts/create_database.sql`，把连接串放入被 Git 忽略的根目录 `.env`；不要将密码写在命令参数或聊天消息里。随后从仓库根目录运行 `python -m alembic upgrade head`，再运行 `python -m scripts.seed_demo_data`。播种脚本可重复执行，但如果已有同 ID 演示记录与本地样例内容冲突会报错，不会重写它。

本机真实 MySQL 的只读核对结果：数据库为 `qa_system`，迁移版本 `0001_initial`，知识库/文档/片段行数分别为 `5/6/6`；5 个知识库均有非空描述，每个知识库至少有一份文档，六份文档均为 `pending`。默认 pytest 还在临时 SQLite 数据库升级到 `head`、执行 Alembic `check`、检查三张表、降级到 `base`，测试播种的幂等性、描述补全和冲突保护；另用占位连接串生成 MySQL 离线迁移 SQL。尚未在 MySQL 上验证完整上传、向量写入和重启后问答。

## 后续边界

下一步才实现上传文件的安全保存、解析、写 MySQL 与 Qdrant、索引状态变更、重复上传、删除补偿以及按知识库问答。现有 FastAPI 路由仍使用固定 `data/model12/*.md` 和内存向量库；即使迁移表已创建，也不会自动获得持久化问答能力。`ingestion_tasks` 暂不建表，等异步索引任务的状态机和重试行为确定后再增加迁移，避免预先造一个没有使用方的结构。
