# 第三阶段 回答生成与系统编排

> 对应原模块 6～8 · [返回项目说明](../README.md) · [上一阶段](第二阶段-向量化与检索.md) · [下一阶段](第四阶段-重排与语义切分.md)

## 一眼看懂本阶段

这阶段把前两阶段的候选片段变成一条可复用的问答调用：问题进入 `RAGCore.answer()`，系统检索内容、构造 Prompt、调用模型并返回 `RAGResult`。后续的重排、聚合和 Web 层都围绕这一个入口扩展。

| 项目 | 本阶段结果 |
| --- | --- |
| 目标 | 将检索片段变成模型可使用的上下文，并输出回答 |
| 输入 | 问题和检索出的片段 |
| 输出 | `RAGResult`：回答、来源片段、证据片段、调用元数据 |
| 关键组件 | PromptBuilder、OpenAIChatLLM、RAGCore |
| 调用方式 | 异步调用大模型；可选接入重排和聚合 |

第二阶段只给出“相关片段”。本阶段确定问题与片段如何交给模型，并提供统一的系统入口，使后续重排、证据聚合和网页接口可以接到同一主链路上。

## 具体完成的工作

### Prompt 与模型客户端

`src/prompts/` 定义提示词构造接口和实现，负责组织问题、候选上下文及回答要求。`OpenAIChatLLM` 使用 OpenAI Python SDK 的异步客户端生成回答，封装模型名、温度、耗时和 token 用量；它也提供后续阶段使用的增量生成方法。提示词构造层不自己检索，模型客户端不负责选择证据。

### RAGCore 统一编排

`RAGCore.answer()` 从 Retriever 取候选，按配置执行 Embedding 重排及答案感知重排。配置了答案聚合器时，直接使用它生成的回答和证据；没有聚合器时，才由 PromptBuilder 构造 Prompt 并调用普通模型生成。两条分支最终都返回 `RAGResult`，不会在聚合回答之后再额外生成一条被丢弃的普通回答。普通问答和流式问答共用 `_retrieve()` 召回与重排流程。该文件是各阶段共同扩展的主链路，不意味着所有可选步骤在当前 Web 配置中都开启。

## 数据流和结果契约

```text
问题 → Retriever → 候选片段 → 可选重排
→ 有聚合器：聚合器生成回答和证据 → RAGResult
→ 无聚合器：PromptBuilder → LLM → RAGResult
```

当前 Web 使用 `FailureAwarePromptBuilder`：它为每个片段加编号和来源，提示模型只依据上下文回答，遇到证据不完整或冲突时表达不确定性。`SimplePromptBuilder` 是另一种可选提示词实现。提示词约束属于给模型的指令，不能保证模型每次都遵守。

`RAGResult.answer` 是最终展示文本；`sources` 保留经重排的 `SearchResult` 候选列表，`evidence_chunks` 是最终展示的证据列表（无聚合器时为空）。`metadata` 保存时延、Top K 和模型调用信息；普通模型调用可记录模型返回的 token 元数据，聚合器内部多次模型调用目前未汇总到这个字段，不能据此估算聚合路径的完整成本。

## 模型配置和调用

`OpenAIChatLLM` 当前默认模型名为 `gpt-6-luna`，通过异步 OpenAI SDK 调用。默认不向接口显式传入 `temperature`，只有调用方指定温度时才发送，以兼容仅接受默认温度的模型。`generate()` 返回正文和 token、耗时元数据；`stream_generate()` 逐段返回模型内容。当前没有统一的模型服务失败重试、调用预算或本地离线模型适配层。

## 验证与限制

原模块记录了控制台问答与 LangSmith 观察结果，表明当时原型链路曾跑通；本轮没有重新调用真实 Chat 模型。旧示例不是固定数据集上的准确率、延迟或成本测量。回答受检索内容和模型生成波动影响；不能仅凭文本流畅判断其有证据支持。
