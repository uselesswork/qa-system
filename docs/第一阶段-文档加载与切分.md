# 第一阶段 文档加载与切分

> 对应原模块 0～2 · [返回项目说明](../README.md) · [下一阶段](第二阶段-向量化与检索.md)

## 一眼看懂本阶段

这一阶段交付的是三个本地文件加载器和一个统一的基础切分流程。TXT、Markdown 读成单份 `Document`，PDF 按页读成多份 `Document`；来源路径与文件类型一路随片段传递。它是代码模块，没有文件上传 API，也没有数据库。

| 项目 | 本阶段结果 |
| --- | --- |
| 目标 | 将不同格式的资料统一成可追溯的文本片段 |
| 输入 | 本地 TXT、Markdown 或 PDF 文件路径 |
| 输出 | `Document` 列表及带来源、位置、编号的 `TextChunk` 列表 |
| 模型调用 | 无 |
| 数据保存 | 本阶段只在内存中返回结果，不写数据库 |

这一阶段解决“后续检索的最小单位是什么”。加载器负责取出正文，清洗器处理文本，切分器再决定每个片段覆盖的字符范围。各环节独立，方便后续替换切分策略。

## 具体完成的工作

### 三种格式接入

| 格式 | 已实现的读取行为 | 保留的来源信息 |
| --- | --- | --- |
| TXT | 按 UTF-8 读取整份文件 | 文件路径、`file_type=txt` |
| Markdown | 按 UTF-8 读取整份文件 | 文件路径、`file_type=md` |
| PDF | 使用 pdfplumber 逐页提取文字，每页形成一份 `Document` | 文件路径、`file_type=pdf`、页码 |

三者统一返回 `Document(content, metadata)`。PDF 某页提取不到文字时，该页正文是空字符串；这里没有 OCR。Markdown 此阶段仍按原文加载，标题感知切分属于第四阶段。

### 清洗与基础切分

`TextCleaner` 对提取文本进行基础清理。`TextSplitter` 默认按 500 字符、80 字符重叠切分，优先在窗口后半段的句末标点回退，减少在句中硬切；如果找不到合适边界，则按长度切。每个片段记录 `chunk_id`、`char_start`、`char_end`，并继承文档来源信息。切分器拒绝“重叠长度不小于片段长度”的配置，也防止重叠造成无新内容的死循环。

## 文件与职责

| 文件 | 作用 |
| --- | --- |
| `src/loaders/document.py`、`base.py` | 统一文档结构与加载接口 |
| `src/loaders/txt_loader.py`、`md_loader.py`、`pdf_loader.py` | 各格式正文提取 |
| `src/processors/cleaner.py` | 文本清洗 |
| `src/processors/chunk.py`、`splitter.py` | 片段数据结构与长度切分 |
| `src/test/test_loader.py`、`test_processor.py` | 模块级验证 |

## 数据流和输入输出

```text
本地路径 → 对应 Loader → Document(content, metadata)
→ TextCleaner → TextSplitter → TextChunk(content, 来源和字符区间)
```

加载器接收的是本地路径，不接收浏览器上传的文件对象。`Document.metadata` 至少记录 `source`、`file_type`，PDF 另有 `page`；`TextChunk.metadata` 在此基础上增加 `chunk_id` 和字符区间。下游向量化器直接消费片段正文，展示证据时还可回看来源。

## 本地使用

从项目根目录运行不调用大模型的加载脚本：

```powershell
.\.venv\Scripts\python.exe -m src.test.test_loader
```

该脚本会打印 `data/model1` 中三种格式的正文。处理器脚本在 `src/test/test_processor.py`，当前 `__main__` 只调用 Markdown 测试；其他两个函数需显式启用。它们是可运行的实验脚本，不是完整的自动化测试套件。

## 验证与限制

本轮用当前 `.venv` 直接加载 `data/model1` 的 TXT、Markdown、PDF：各返回 1 份文档，正文长度均为 37 字符，经清洗和默认长度切分后各得到 1 个片段。原模块另外记录了中英混排、片段过短、重叠重复等观察。这个小样本只证明基本读取与传递，不证明复杂文档处理质量。

`TextCleaner` 用 `\s+` 将连续空白压成单个空格，因此会丢失原有换行和 Markdown 标题行结构。长度切分能建立检索单位，但不能保证语义完整。当前 Web 实际只加载 `data/model12/*.md`；扫描版 PDF、非 UTF-8 的 TXT 和复杂 PDF 排版不在现有处理能力内。
