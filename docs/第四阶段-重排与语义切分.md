# 第四阶段 重排与语义切分

> 对应原模块 9～10 · [返回项目说明](../README.md) · [上一阶段](第三阶段-回答生成与系统编排.md) · [下一阶段](第五阶段-答案与证据聚合.md)

## 一眼看懂本阶段

这阶段增加了两种质量控制：候选片段在进入 Prompt 前再次排序，以及根据 Markdown 标题决定片段边界。重排和标题切分都已接入当前 Web。后续工程重构修正了标题正则及清洗时丢失换行的问题，现在普通 `# 标题` 能进入标题切分分支；没有标题的 Markdown 仍回退到长度切分。

| 项目 | 本阶段结果 |
| --- | --- |
| 目标 | 减少切分破坏语义、以及召回结果顺序不理想的问题 |
| 输入 | 原始文档和召回候选片段 |
| 输出 | 更合适的片段边界、经过二次排序的候选列表 |
| 当前 Web 状态 | Embedding 重排与标题切分均已接入；示例文档在启动时重新切分与向量化 |

## 具体完成的工作

### Embedding 重排

`EmbeddingReranker` 在初次召回之后使用问题向量与候选向量重新计算余弦相似度、排序并截断到目标 Top K。RAGCore 为粗排前扩大召回数量，给二次排序留出候选空间。`SimpleRetriever.retrieve_with_vector()` 把首次检索的问题向量一并返回，重排器不再重复请求同一问题的 Embedding；其他检索器未提供向量时才回退计算。它仍使用与检索接近的语义信号，所以不能解决“片段谈论同一主题、却没有真正回答问题”的所有情况。

### 标题感知切分

`SemanticSplitter` 对 `file_type=md` 的文档先调用 `HeadingSemanticSplitter`；若没有得到片段，回退到第一阶段的 `TextSplitter`，其他格式直接使用长度切分。现在 `TextCleaner.clean(..., preserve_newlines=True)` 在 Markdown 标题切分路径保留换行，标题正则匹配行首一级至六级标题。标题前有正文时单独保留，不再静默丢弃。标题片段带 `heading`、`semantic=heading`、`chunk_id`、`char_start` 和 `char_end` 元数据，位置对应清洗后的文本。普通长度切分仍可使用清洗器默认的压平空白行为。

## 数据流与对比实验

```text
设计：Markdown → 标题切分（失败时回退长度切分）→ Embedding → 召回
当前核对：# Title → 标题片段；无标题文本 → 长度切分
问答：初始召回最多 10 片段 → Embedding 重排 → 最多 5 片段
```

原模块 9 比较有无重排：初始候选只有少量片段、两层又使用相似向量逻辑时，排序几乎不变；加入干扰片段后，部分案例的答案片段上升。模块 10 把普通长度切分和语义切分与有无重排交叉比较，观察到部分含噪声示例中重排有帮助。结论应限定在这些示例，不能推断语义切分或重排在任意资料集上都提高准确率。

| 原实验组合 | 原记录的主要观察 | 现在应如何解读 |
| --- | --- | --- |
| 普通切分、不重排 | 前排片段可能混有噪声和答案 | 基线示例，非总体质量指标 |
| 普通切分、Embedding 重排 | 部分示例把更有用的片段排到前面 | 说明候选空间和噪声设计会影响重排效果 |
| 标题切分、不重排 | 原截图中与普通切分差异有限 | 切分缺陷已修复，旧截图不能作为修复后质量指标 |
| 标题切分、Embedding 重排 | 原截图中答案片段排序较靠前 | 需要在同一问题集上重新比较修复后的效果 |

检索和重排使用相近的余弦逻辑时，同一批片段重新打分可能不会改变顺序；原模块 9 对这一现象给出了合理解释。标题识别和换行保留已经修复，但要判断语义切分是否真的改善回答质量，仍需用相同问题和标注片段重新比较。标题片段目前按整节输出，不限制单节长度；很长的章节仍可能使 Prompt 过大。

## 验证与限制

离线回归已覆盖带导言和两级标题的 Markdown、字符偏移、无标题回退，以及检索加重排时只计算一次问题向量；还用假 Embedding 验证 Web 组装后的片段含 `heading` 元数据。未运行真实模型或重新评估问答准确率。原模块 10 的截图只反映当时的实验记录；PDF 和 TXT 不会按章节语义解析，Embedding 重排仍无法直接检验事实支持度。第五阶段的证据聚合与第八阶段的可选细排处理的是另外两个位置的问题。
