# 阶段 15：本机完整容器运行与交付

> [返回 README](../README.md) · [故障排查](故障排查.md)

`compose.yaml` 单独运行 Web、MySQL、Redis、Qdrant、Celery worker、beat 和一次性迁移容器。Web 只发布到宿主机 `127.0.0.1`，不构成公网部署。与旧的 `compose.ingestion.yaml`、`run.cmd` 是两套运行方式；不要同时让它们使用同一宿主端口或把旧数据卷误认为新栈数据。

## 首次启动

安装 Docker Desktop，并在项目根目录执行：

```powershell
Copy-Item .env.compose.example .env.compose
```

编辑被 Git 忽略的 `.env.compose`：填写真实 `OPENAI_API_KEY`、`OPENAI_BASE_URL`，并将两个 MySQL 示例密码换成各自随机的英数字密码。`MYSQL_PASSWORD` 会直接嵌入数据库 URL，包含 `@`、`:`、`/` 等符号时要先做 URL 编码；最简单的方式是使用十六进制随机密码。已有 `.env` 不会被容器读取。若本机 8090 已由 `run.cmd` 使用，将 `WEB_HOST_PORT` 改为 8091。

```powershell
docker compose --env-file .env.compose config --quiet
docker compose --env-file .env.compose up -d --build
docker compose --env-file .env.compose ps
```

等待 `migrate` 显示 `Exited (0)`、`mysql` 和 `redis` 为 healthy、`web` 为 healthy，再打开 `http://127.0.0.1:8090/`（改端口时用相应端口）。`migrate` 在 Web/worker 启动前执行 `alembic upgrade head`。上传文件在 `uploads_data`，MySQL、Qdrant、Redis 分别使用独立命名卷，beat 计划文件在 `beat_data`。重新运行 `up -d --build` 不会清空这些卷。

检查服务与无密钥存储冒烟：

```powershell
docker compose --env-file .env.compose exec -T web python -m scripts.smoke_services
```

冒烟脚本检查 MySQL 表、Redis `PING`、Qdrant 写入和删除，不调用模型。随后可在网页注册测试账号、上传独立测试文档，等待“已索引”，关闭联网提问并核对依据。真实 Embedding/LLM 调用会产生费用。

## 日常操作

```powershell
docker compose --env-file .env.compose ps
docker compose --env-file .env.compose logs --tail=100 web worker beat
docker compose --env-file .env.compose up -d --build
docker compose --env-file .env.compose down
```

`down` 停止并删除容器，保留命名卷。不要用 `down -v`，它会删除本栈数据。修改 `.env.compose` 后重新 `up -d --force-recreate` 使变量生效。升级代码前备份数据；若新版有数据库迁移，回滚旧镜像前先确认迁移是否可逆。代码回滚可检出旧提交后重新 `up -d --build`；数据恢复使用下节备份，不应只靠旧镜像回滚数据库结构。

## 备份与恢复

维护窗口先 `down`，确保 MySQL 与 Qdrant 文件一致，再备份五个命名卷。以下命令在 PowerShell 中运行，`$backupDir` 可改为另一块磁盘上的绝对目录：

```powershell
docker compose --env-file .env.compose down
$backupDir = (New-Item -ItemType Directory -Force -Path .\backups\stage15).FullName
foreach ($name in 'mysql_data','qdrant_data','redis_data','uploads_data','beat_data') {
  docker run --rm --mount "type=volume,source=qa-system-full_${name},target=/source,readonly" --mount "type=bind,source=$backupDir,target=/backup" alpine tar -C /source -czf "/backup/${name}.tgz" .
}
```

恢复时先确认备份文件齐全，并确保目标是全新的空卷；**不要直接覆盖仍在使用的卷**。在另一台电脑创建同名空卷后逐个解包，最后 `up -d --build`。例如恢复一个卷：

```powershell
docker volume create qa-system-full_mysql_data
docker run --rm --mount "type=volume,source=qa-system-full_mysql_data,target=/target" --mount "type=bind,source=$backupDir,target=/backup,readonly" alpine tar -C /target -xzf /backup/mysql_data.tgz
```

对其余四个卷使用对应名称重复。备份目录包含账号、上传资料与向量，按敏感数据保存，不提交 Git。`.env.compose` 也需单独安全迁移；卷备份不包含密钥配置。恢复后运行 `ps`、`smoke_services`，再从页面检查一条既有会话。

## CI

`.github/workflows/ci.yml` 在干净检出上运行 Python 3.11 语法检查和无密钥 pytest；另一任务启动 MySQL、Redis、Qdrant，执行 Alembic 迁移及 `scripts.smoke_services`。CI 不持有真实模型密钥，也不进行付费问答。真实模型和浏览器验收仍按阶段 11～14 的记录人工执行。
