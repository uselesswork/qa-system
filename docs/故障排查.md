# 完整容器栈故障排查

> [运行与部署](运行与部署.md)

先运行 `docker compose --env-file .env.compose ps`，再用 `docker compose --env-file .env.compose logs --tail=100 服务名` 查看具体错误。以下命令均在项目根目录执行。

| 现象 | 检查与处理 |
| --- | --- |
| `config` 报缺少密码 | 从 `.env.compose.example` 创建 `.env.compose`，填写 `MYSQL_PASSWORD` 和 `MYSQL_ROOT_PASSWORD`。 |
| Web 端口占用 | 将 `.env.compose` 的 `WEB_HOST_PORT` 改为未占用端口，重新 `up -d`。不要停止另一套 `run.cmd` 服务来掩盖冲突。 |
| `migrate` 非 0 退出 | 查看 `logs migrate mysql`；确认 MySQL healthy、密码是 URL 安全字符，迁移版本与代码一致。修复后重新 `up -d migrate`。 |
| Web 未 healthy | 查看 `logs web`；检查 API key 是否存在以及 8090 容器内端口。`GET /` 只验证进程可响应，真实存储再运行 `smoke_services`。 |
| 上传一直待索引 | 查看 `logs worker beat redis`；确认 worker、beat 使用同一 Redis 和共享上传卷。beat 每分钟补投 `pending`，超时 `indexing` 任务 30 分钟后恢复。 |
| 索引失败 | 查看页面任务错误与 `logs worker qdrant`。修复模型密钥或 Qdrant 后点“重试索引”；不要删除文档来重试。 |
| 重建后数据消失 | 检查是否用了 `down -v`、更改 Compose 项目名或换了 Docker context。数据位于 `qa-system-full_*` 命名卷。 |
| 联网返回错误 | 核对 `OPENAI_BASE_URL`、密钥和模型服务是否支持 Responses `web_search`；查看 `logs web`，无需把密钥贴入日志或工单。 |

更新失败时先保留当前卷并按[备份与恢复](运行与部署.md#备份与恢复)制作副本。代码回滚不能自动撤销数据库迁移；如需恢复数据库，使用升级前的整套卷备份。
