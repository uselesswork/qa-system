# 第十二阶段 可选联网搜索（规划，未实现）

> [项目总览](../README.md) · [上一阶段](第十一阶段-用户权限与会话持久化.md)

## 阶段目标与当前状态

阶段 11 完成真实模型与浏览器端到端验收后，增加由用户主动选择的联网搜索。当前项目没有联网搜索接口或页面入口；知识库没有 `ready` 文档时，按库问答返回 409。本文是下一阶段的实施计划，不代表功能已经可用。原定的异步索引、评测、容器化、安全加固和展示工作依次顺延为阶段 13～17。

## 交互与数据边界

1. 当前知识库没有 `ready` 文档时，页面提示上传资料；若有 `failed` 文档，保留重试索引入口。同时提供独立的“联网搜索”操作，由用户明确触发。默认知识库问答不自动访问公网。
2. 联网回答标明“网页来源”，展示标题和可访问链接；知识库回答继续标明本地文档及片段。网页结果不伪装为已上传文档，也不自动写入知识库或 Qdrant。
3. 发起搜索只传用户当前选择联网的问题及必要参数；不把私有知识库文档、其他用户的内容或整段会话历史自动发送给搜索服务。回答及来源若写入聊天历史，要保留来源类型和链接，以便刷新后仍能区分。
4. “知识库为空”和“已有文档但没有相关证据”分别处理。后者先明确无足够证据；是否提供另行联网的入口，要在实现时结合检索阈值和评测确定，不能把低相关结果直接当成空库。

## 拟实施工作

- 先确定联网服务、模型调用方式、费用、速率限制和失败行为。当前生成调用使用 Chat Completions，不能假定给现有请求加一个参数就能联网；若采用 OpenAI 内置搜索，按[官方 Web Search 文档](https://developers.openai.com/api/docs/guides/tools-web-search)评估接口及引用结构。
- 设计独立的联网请求与响应结构，至少包含回答、来源类型、标题、URL 和必要的错误信息。后端仍按登录用户校验会话归属；页面清楚呈现当前模式。
- 对搜索超时、无结果、无有效来源、凭据无效和服务费用进行处理。联网不可用时提示用户，不伪造来源，也不覆盖原有知识库问答结果。
- 增加假搜索服务的离线测试，验证未主动选择时不会联网、来源不会混淆、跨账号会话仍隔离；真实联网联调单独记录调用量、费用和可复现结果。

## 验收口径

空知识库的用户可以选择上传资料或主动联网；联网回答带可核对的网页来源。默认知识库模式的 409 与现有权限边界保持明确，失败索引仍可重试。搜索失败有可理解的错误，聊天历史中的网页引用在刷新后仍能正确显示。只有实现并完成上述测试后，才能把本阶段标为完成。

当前 `.env` 中的模型凭据仍需有效；新增联网能力不会修复无效 API Key 导致的 Embedding 索引失败。
